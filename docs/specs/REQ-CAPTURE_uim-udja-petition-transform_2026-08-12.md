## §1 Context

A first-party insurance suit was drafted this session: an original petition under the Texas declaratory-judgments statute against the client's own underinsured-motorist (UIM) carrier, filed as a follow-on matter after the underlying third-party motor-vehicle case settled. Two inputs drove the draft: (a) the firm's own MVA-UDJA petition exemplar, used as the structural and formatting guide, and (b) the underlying case's original petition, used as the facts source. The work was a document-to-document transform: same plaintiff and occurrence, new defendant (the carrier), new instrument posture (original petition in a new cause), with the former defendants recast as non-party underinsured motorist and settling owner.

## §2 Requirements observed

- **REQ-01 — Follow-on matter creation.** Practice moment: the settled third-party case spawned a first-party UIM/UDJA suit sharing plaintiff, occurrence facts, counsel, and (in changed roles) the former defendants. Capability: create a linked follow-on matter that inherits selected entities and facts from a source matter, with explicit role transforms, instead of starting blank. Priority: now.
- **REQ-02 — Party-role transforms across linked matters.** Practice moment: the underlying suit's defendant driver became the non-party "underinsured motorist"; the co-defendant vehicle owner became a non-party settling party; the client's own insurer entered the defendant slot. Capability: the roster model needs per-matter roles with cross-matter role history, so an entity can be "defendant in matter A, non-party tortfeasor in matter B." Priority: soon.
- **REQ-03 — Instrument transform as a first-class operation.** Practice moment: the instruction was literally "redraft document X using document Y as a guide." Capability: "draft instrument for matter B using exemplar E for structure and matter A for facts" as a named operation, with the field-mapping (who maps to whom) surfaced for attorney confirmation. Priority: now.
- **REQ-04 — Consistency checking must sweep headers and footers.** Practice moment: the exemplar carried THREE different insurer identities — one in the caption, a second in the body, and a third in the running page footer. Caption-vs-body checking alone would have missed the footer. Capability: the roster-driven consistency checker must sweep every story of the document, including headers, footers, and footnotes. Priority: now. (Extends the caption-body-drift error class recorded in the roster-mining packet.)
- **REQ-05 — Numbering-restart fragility.** Practice moment: the exemplar's second numbered list was defined with a hard-coded start value chained to the first list's final count; inserting one fact paragraph silently produced a duplicate visible number until the start value was manually bumped. Capability: generated instruments should use continuous logical numbering, and a render-time lint should verify the visible numbering sequence is gapless and duplicate-free. Priority: now.
- **REQ-06 — Insurer entity type drives jurisdictional pleading.** Practice moment: the exemplar's defendant paragraph pleaded Texas citizenship — accurate for the exemplar's county-mutual defendant, inaccurate (and removal-relevant) for a foreign insurer in the new defendant slot. Capability: model insurer entity type (county mutual vs. foreign insurer vs. domestic company) and flag citizenship/diversity implications whenever the defendant slot changes. Priority: soon.
- **REQ-07 — Registered agent as entity-level data.** Practice moment: the service paragraph's agent name and address were inherited from the exemplar and had to be independently checked. Capability: registered-agent name/address stored per entity with a verify-before-service state and staleness date, never copied as prose. Priority: soon.
- **REQ-08 — Relief bracket as a picklist field.** Practice moment: the rule-mandated relief statement had to be swapped between fixed statutory brackets, and the exemplar's bracket did not match the new case. Capability: the pleading template renders the correct bracket clause from a per-matter picklist among the fixed options. Priority: now.
- **REQ-09 — Citation currency in the citation bank.** Practice moment: the exemplar carried a slip-opinion citation (docket number + Westlaw cite) for a case long since published in the reporter. Capability: citation bank stores the canonical current cite with verification state and flags slip cites that likely have reporter cites by now. Priority: soon. (Extends the citation-bank requirement from the deficiency-handling packet.)
- **REQ-10 — Instrument posture as a render parameter.** Practice moment: converting a "first amended petition" exemplar into an "original petition" changed the title, required deleting the certificate of service (an original petition is served with citation, not by certificate), and changed the footer's instrument name. Capability: posture (original / amended / supplemental) is a render parameter that drives title, certificate-of-service inclusion, and footer text together. Priority: now.

## §3 Data-model and template implications

- Linked-matter graph: matters connect by a "follow-on" edge carrying role-transform mappings ({{party}} was {{role_a}} in source, is {{role_b}} in target).
- Merge fields surfaced by this instrument: {{uim_carrier}}, {{uim_carrier_short}}, {{underinsured_driver}}, {{vehicle_owner}}, {{uim_policy_limits}}, {{relief_bracket}}, {{registered_agent_block}}, {{court_number}}, {{county}}, {{case_short_style}}, {{instrument_name}}.
- Footer merge fields ({{case_short_style}} + {{instrument_name}} + page X of Y) are part of the format profile, not an afterthought — REQ-04's practice moment is the proof.
- Template candidate flagged for distillation: template_petition_udja-uim-carrier.md (structure: discovery level → parties → jurisdiction/venue → facts incl. underinsured status, conditions precedent, and settlement/exhaustion → UDJA cause with lettered declarations a–g and roman-numbered damage categories → interest → relief bracket → jury demand → disclosure sections → e-service designation → prayer with declaratory-fees request).
- The declarations block behaves as an ordered list of typed declarations (liability, damages-compensability, coverage-fit, limits, damages-by-category, offset-excess, amount-with-fees) — each is a data item, not prose.

## §5 Open questions for the design side

1. Should a follow-on matter inherit the source matter's evidence and discovery products (crash report, records indices, deposition transcripts) as linked references, or as copies — and does privilege/work-product tracking differ between the two?
2. When the consistency checker sweeps headers and footers for party identifiers, how should it distinguish a deliberate short-form (a footer that intentionally uses a shortened case style) from genuine drift against the roster?
3. Should "non-party tortfeasor" be a formal roster role in first-party coverage suits — the person appears throughout the declarations and facts but is not a party — and if so, does the checker verify their name consistency with the same rigor as parties?
4. Should instrument posture (original vs. amended) automatically include or exclude the certificate of service at render time, or only warn the attorney that the combination looks wrong?
5. Is entity-type-driven removal-exposure flagging (foreign insurer in the defendant slot plus a relief bracket above the federal jurisdictional threshold) in scope for the software's deadline/strategy engine, or is that attorney-only analysis the software should merely annotate?
6. Should the numbering lint (REQ-05) run automatically on every rendered instrument, or also exist as a standalone document-check tool that can be pointed at exemplars and incoming documents?
